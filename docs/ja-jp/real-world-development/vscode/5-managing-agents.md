GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、自分のマシンでリアルタイムに実行されるツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を承認または却下し、エディターを離れずに追加のプロンプトを送って作業を調整・拡張できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッション中にエージェントへ指示を追加し、ハイコントラストとともにライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードも切り替えられるようにしたいとのことです。新しい会話を最初から始めるのではなく、既存のセッションに指示を加えて作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各ステップ、調査したファイル、実行したコマンド、提案された編集が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともに、チャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツールの操作を確認します。ファイルの読み取り、ファイル編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると、変更を承認します。
   - **Undo** を選択すると、変更を元に戻して、エージェントにもう一度作業させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更した作業セット全体を確認できます。

> [!NOTE]
> ツールの操作に権限が必要な場合 (ターミナルコマンドの実行など)、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、実施した変更をまとめたメッセージが表示されます。

## エージェントにライトモードを追加するよう依頼する

ハイコントラストモードができたので、同じ会話でライトモードの切り替えも追加します。同じチャットセッションを続けることで、エージェントは前の作業、変更したコンポーネント、スタイルの方針、設定した local storage のパターンなどのコンテキストを保持します。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントはすでに行った変更を確認してから、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、追加される編集を1つずつ確認し、各差分で **Keep** または **Undo** を使います。
4. エージェントの方針が希望と異なる場合 (たとえばトグル UI を意図しない形でリファクタリングする場合) は、チャット入力欄の隣にある **Stop** ボタンで停止し、明確な追加指示を送ります。

> [!TIP]
> 作業中のセッションに指示を送る方が、最初からやり直すよりも速く進められます。追加のプロンプトで変更を依頼できます。「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」などの調整や、「3つ目のトグルは追加せず、既存の設定パネルにライトモードを組み込む」といった方向修正、「両方のトグルにキーボードショートカットも追加する」といった範囲の拡張が可能です。

## 作業セットをレビューする

変更をコミットする前に、エージェントが変更したファイルをすべて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが示したアクセシビリティのパターン、ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して案内しました。ファイル編集を1つずつレビューし、変更を承認または却下し、コンテキストを失わずに追加のプロンプトを送って作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または却下しました。
- 作業中のセッションに追加のプロンプトを送って、作業を案内しました。
